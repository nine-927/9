# step7_stack.c · 撞堆检测（Stack 机制）

## 文件职责
让移动检测"认识"已固化的方块堆：方块会落在堆顶而不是穿过它，terrace 台阶由此形成。

## 与 Step 6 Lock 的区别（确认结论：不重复、无偏差）
| | Lock（Step 6） | Stack（Step 7） |
|---|---|---|
| 角色 | **写入方**：产生堆 | **读取方**：让堆生效 |
| 触发条件 | 仅在 `can_place(x, y+1)` 失败（触底）时 | 每一次移动尝试（按键移动、自动下落前） |
| 作用范围 | 把方块格子写进 `board` 并重画 | 只读 `board`，不写任何数据 |
| 对棋盘影响 | `board` 内容增加 | 无，只影响"这次移动是否合法" |

## 主要函数
- `can_place(gx, gy)`：唯一改动点，新增一行 `if (board[y][x] == 1) return 0;`
- 其余函数与 Step 6 完全一致。

## 关键逻辑与数据流
```
按键 / 自动下落 ─> can_place(nx, ny)
                     ├─ 撞墙        ─> 拒绝
                     ├─ 撞堆(board) ─> 拒绝   <-- 本步新增
                     └─ 合法        ─> 移动
```

## 与其他文件的依赖关系
- 上游：Step 6 引入的 `board` 数组是本机制的数据来源。
- 下游：Step 8 的 `spawn()` 出生检查同样依赖本判定。

## 注意事项
- 判定顺序无所谓先后，撞墙与撞堆任一命中即拒绝。
